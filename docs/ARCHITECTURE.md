# البنية التقنية

## الملفات

| المسار | الوصف |
|---|---|
| `index.html` | التطبيق المنشور (ناتج البناء، لا يُعدَّل يدوياً) |
| `sw.js` | Service Worker للعمل دون اتصال والتحديث؛ رقم `jaliyat-vN` يُرفع مع كل نشر |
| `portal.html` | بوابة المنسقين العامة (رابط برمز لكل جالية) |
| `verify.html` | التحقق من تصريح الدرس عبر الباركود |
| `auth.html` | صفحة الرجوع لتسجيل دخول Microsoft (MSAL) |
| `jaliyat-copilot.zip` / `bridge/` | الجسر (إضافة MV3) — Copilot + واتساب ويب داخل النظام |
| `src/base/index.html` | النواة الأصلية (العرض، الحالة `S`، الدوال الأساسية) |
| `src/modules/add*.js` | الوحدات بالترتيب؛ كل وحدة تضيف ميزة دون تعديل النواة |
| `src/modules/add*.css` | الأنماط الإضافية |
| `src/build.py` | يجمع النواة + الوحدات + يطبّق `config.json` ثم يضغط عبر `minify.js` |
| `src/config.json` | اسم الوزارة/الإدارة/القسم ومشروع Supabase — للنسخ لجهة أخرى |

## نمط الوحدات

- **الحالة:** كائن واحد عام `S` (المستخدم `S.me`، البيانات `S.acts`، `S.tasks`، `S.wq`...)، والعرض `render()` يستدعي `vXxx()` حسب `S.view`، ثم `afterRender()`.
- **التوسعة بالتغليف:** `const _f = f; f = function(){ ... _f() ... }` بأسماء فريدة لكل وحدة (مثل `_vHome42`). لا تُستخدم `const` للدوال القابلة للتغليف.
- **الأحداث:** مستمع `click` واحد لكل وحدة على `document` يعتمد `data-*` (مثل `data-task`، `data-go`، `data-wq`).
- **الروابط العميقة:** `openLink("#task:<id>")`، `#wq:<id>`، `#rec:`، `#dec:`، `#permit:`.
- **الأولويات:** `priorities()` تُرجع بنود «أولويات اليوم»؛ كل وحدة تضيف بنودها.
- **«جديد»:** مصفوفة `NEWF` — كل ميزة تضيف سطراً يظهر للموظفين حتى يطّلعوا.
- **الأدوار:** `S.admin` (مدير النظام/رئيس القسم)، `S.canWrite` (محرر)، والمشاهد. التحقق الفعلي في RLS بقاعدة البيانات عبر `my_role()`.

## التكاملات

- **وثيقة (watheqa.awqaf.gov.kw):** مهمة مجدولة تفتح وثيقة في متصفح الموظف (بجلسته، دون كلمات مرور)، تقرأ الكتب وترسلها إلى Edge Function `watheqa-ingest` → جدول `watheqa_docs`. الكتب المرسلة من «إنجاز» تُوضع في `watheqa_outbox` وتحفظها المهمة نفسها مسودة في السكرتارية بعد بوابة تدقيق.
- **واتساب:** واتساب ويب داخل النظام عبر الجسر 2.3 (يزيل منع الإطار ويقدّم الطلب كصفحة). كل الإرسال يمر عبر `waInside()` وسجل `wa_sends` / `wq_notify`.
- **Copilot:** عبر الجسر (إطار M365) أو MSAL/Graph للحسابات.
- **OneDrive:** نسخة احتياطية لكل مستخدم بحسابه (`settings.onedrive:<userId>`).
- **الإشعارات:** Web Push عبر Edge Function `notify-push` ومحفّزات قاعدة البيانات.

## الاختبار

اختبارات Playwright تحمّل `index.html` مع Supabase وهمي وبيانات تجريبية، وتتحقق من كل ميزة (العرض، الأزرار، عدم وجود أخطاء JS) قبل النشر.
