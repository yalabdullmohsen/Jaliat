# نسخ «إنجاز» لقسم أو إدارة أخرى

النظام مصمَّم ليُنسخ كما هو: كل ما يخص الجهة في `src/config.json` وفي بيانات قاعدة البيانات، لا في الكود.

## الخطوات

1. **المستودع:** Fork أو نسخة جديدة من هذا المستودع، وفعّل GitHub Pages على الفرع `main`.
2. **قاعدة البيانات:**
   ```bash
   # من المشروع الحالي (يحتاج كلمة مرور قاعدة البيانات أو صلاحية المالك)
   supabase db dump --schema public -f schema.sql
   # في مشروع Supabase الجديد
   psql "<connection string>" -f schema.sql
   ```
   ثم انشر الـ Edge Functions المطلوبة (`notify-push`, `manage-users`, و`watheqa-ingest` إن احتاجوا وثيقة)، وأنشئ bucket التخزين `requests` (خاص).
3. **الإعداد:** عدّل `src/config.json`:
   ```json
   {
     "ministry": "وزارة الشؤون الإسلامية",
     "admin_unit": "اسم الإدارة",
     "section": "اسم القسم",
     "supabase_url": "https://<new-ref>.supabase.co",
     "supabase_anon_key": "<anon key للمشروع الجديد>"
   }
   ```
   البناء يستبدل الأسماء والمشروع في كل النظام تلقائياً.
4. **البناء والنشر:** `cd src && python3 build.py && cp index.html ../index.html`، وعدّل مسار الموقع في `bridge/manifest.json` و`bridge/sw.js` (`yalabdullmohsen.github.io`) إلى نطاق النسخة الجديدة، ثم أعد ضغط `jaliyat-copilot.zip`.
5. **أول حساب:** سجّل المستخدم الأول من Supabase Auth واجعل دوره `admin` في `profiles`، ثم يضيف هو الموظفين من «المستخدمون والصلاحيات».
6. **البيانات المرجعية:** أدخل الجاليات/الجهات والمنسقين والمساجد من صفحاتها (أو استوردها إكسل)، فتعمل بقية الصفحات عليها.

## ما يتغيّر غالباً بين الجهات
- المجموعات في القائمة الجانبية: `_groups` في `src/build.py`.
- أنواع القرارات والتوصيات: `DEC_K`, `REC_K` في `modules/add31.js`.
- قواعد كتب وثيقة (المستلمون والصياغة): `letterHTML` في `modules/add11.js`.
- قيمة الخطبة والمكافآت: من صفحة المكافآت (إعداد `sermon_rate`).

## لإدارة أكبر (عدة أقسام)
الأبسط: نسخة لكل قسم (عزل تام للبيانات والصلاحيات). وإن أُريد نظام واحد لعدة أقسام: أضف عمود `unit` للجداول الرئيسية وشرطاً عليه في سياسات RLS و`my_role()` — البنية الحالية (جداول jsonb + RLS مركزية) تسمح بذلك دون إعادة كتابة الواجهة.
